# 1. PROJECT OVERVIEW

## 1.1 What is Yegna AI?

Yegna AI (የኛ AI - meaning "Our AI" in Amharic) is an Ethiopian AI training platform that combines:

- **Crowdsourced AI Training**: Users complete simple tasks to train AI models
- **Earning System**: Users earn ETB for completing tasks
- **MLM Referral Network**: 5-level referral commission system
- **Membership Tiers**: 9 levels from Intern to D8 Master Elite

## 1.2 Core Value Proposition

- Help build Ethiopia's first major AI
- Earn daily income
- Build a team and earn passive commissions
- Government partnership with Ethiopian AI Institute

## 1.3 Tech Stack Summary

| Layer | Technology | Version |
|-------|-----------|---------|
| Frontend | Next.js | 14.x |
| Backend | Express.js | 4.x |
| Database | PostgreSQL (Neon) | 15+ |
| Language | JavaScript (JSX) | ES2022 |
| Styling | Pure CSS | Custom Design System |
| i18n | i18next + react-i18next | Latest |
| Data Fetching | react-query | 3.x |
| Forms | react-hook-form | 7.x |
| Icons | lucide-react | Latest |
| Build Tool | Turborepo | 1.x |
| Deployment | Vercel | Latest |
| Package Manager | npm workspaces | 9+ |

# 3. MONOREPO STRUCTURE

## 3.1 Why Monorepo?

- Single repository for frontend, backend, and shared packages
- Shared code between apps (config, utils, i18n)
- Consistent versioning
- Single `npm install` for all dependencies
- Turborepo for optimized builds

## 3.2 Workspace Organization

```
yegna-ai-platform/          # Root
├── apps/                   # Applications
│   ├── web/               # Next.js Frontend
│   └── api/               # Express Backend
├── packages/              # Shared Packages
│   ├── config/           # JSON Configuration
│   ├── ui/               # Shared UI Components
```

## 5.2 Middleware Chain

```
Request → CORS → Helmet → JSON Parser → Rate Limiter → Routes → 404 → Error Handler
```

### Middleware Types:
1. **CORS** - Cross-origin resource sharing
2. **Helmet** - Security headers
3. **JSON Parser** - Parse request bodies
4. **Rate Limiter** - Prevent abuse (100 requests/15min)
5. **Auth Middleware** - Verify JWT token
6. **Admin Middleware** - Check admin role
7. **Validation Middleware** - Validate request data
8. **Error Handler** - Centralized error handling

## 5.3 Controller → Service → Model Pattern

```
Controller: Handles HTTP requests/responses
    ↓
Service: Contains business logic
    ↓
Model: Direct database queries (parameterized SQL)
```

# 9. AUTHENTICATION & SECURITY

## 9.1 Authentication Flow

```
1. User registers/logins
2. Backend validates credentials
3. Backend generates JWT tokens (access + refresh)
4. Tokens stored in cookies (js-cookie)
5. Access token sent in Authorization header
6. Backend middleware verifies token
7. User data attached to request object
```

## 9.2 JWT Tokens

- **Access Token**: 7 days expiry
- **Refresh Token**: 30 days expiry
- **Secret**: `JWT_SECRET` environment variable

## 9.3 Security Measures

### Implemented:
- ✅ Parameterized SQL queries (prepared statements)
- ✅ Input validation (regex, type checking)
- ✅ XSS protection (helmet)
- ✅ Password hashing (bcrypt, 10 rounds)
- ✅ Rate limiting (express-rate-limit)
- ✅ CORS with credentials
- ✅ JWT authentication
- ✅ Admin role checking
- ✅ Sanitization of user input

### Database Security:
- UUID primary keys (not sequential)
- Foreign key constraints
- Unique constraints on email, username, referral_code
- ON DELETE CASCADE for related records

## 11.2 Commission Types

### Direct Referral Commission
- When a referred user deposits
- 10% of deposit amount
- Requires referrer to be D1 or higher

### Team Task Commission
- When downline members complete tasks
- Level 1: 10% of task reward
- Level 2: 5% of task reward
- Level 3: 3% of task reward
- Level 4: 2% of task reward
- Level 5: 1% of task reward
